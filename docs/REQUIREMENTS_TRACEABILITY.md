## Security review

Seven verified findings from the security review, each fixed with regression tests. No domain
file was changed (`app/domain/*` is the frozen contract): the extra database operations the
fixes need are declared as structural protocols in `app/services/ports.py` (`SecureStore`), which
`SqlStore` implements without importing the services layer, so all six import-linter contracts
are unchanged. One migration, `alembic/versions/0002_security_hardening.py`, adds `locks.owner`
and three tables (`lookup_budget`, `suppressions`, `admin_sessions`), none holding PII.

| # | Finding | Resolution | Regression tests |
|---|---|---|---|
| 1 | **[medium]** RocketReach daily cap bypassed when recording a lookup fails (`app/services/origination.py`) | **Fixed.** Attempts are counted, not successes. ### New operator actions

- Set `SUPPRESSION_SECRET` (32+ characters, the same on web and cron, never rotated) before the next production
  deploy. Production refuses to start without it.
- Optional: `TRUSTED_PROXY_HOPS` (default `1`) if another proxy is ever put in front of Railway's edge.
- Deploy web first: it runs migration `0002_security_hardening`.
